강의별 AI 교수 답변 · 자동 질문 생성

251190b

강의를 운영할 때 채팅창이 비어 있으면 아무도 먼저 입을 떼지 않습니다. 강의마다 운영자가 켜고 끌 수 있는 토글 두 개를 만들었습니다.

옵션동작
AI 교수 답변
ai_answer		 수강생이 질문을 올리면 백그라운드로 교수 입장의 답변을 생성해 붙입니다. 해당 슬라이드의 내레이션을 컨텍스트로 넘기므로 강의 내용에 근거해 답합니다.
자동 질문 생성
auto_question		 학생이 쓴 것처럼 자연스러운 질문(한국식 이름)을 만들고 교수 답변까지 함께 답니다. 실제 수강생 질문을 소스로 활용해 가장 자주 나온 궁금증을 학생풍으로 재구성합니다.

스팸이 되지 않게 하는 규칙

AI가 질문을 무한정 만들어내면 채팅창이 가짜 대화로 뒤덮입니다. 슬라이드당 상한을 둡니다.

allowed = (aq == 0) or (aq < AI_QUESTION_CAP and aq < rq)
#  aq = 이미 만든 AI 질문 수,  rq = 실제 수강생 질문 수,  CAP = 3
#  → 마중물 1개는 허용, 그 뒤로는 실제 질문 수를 절대 넘지 않는다
놓치기 쉬운 함정

AI가 만든 질문·답변이 그대로 학습 분석에 섞이면 CQI 보고서가 오염됩니다. chat_messages.origin 컬럼(student / ai_student / ai_teacher)을 두고, analytics 집계와 키워드 추출에서 origin = 'student' 만 세도록 했습니다.

설정은 lecture_settings 테이블에 따로 두어 ZIP 재업로드나 강의 재생성과 독립적으로 유지됩니다. 서비스 로직은 app/services/ai_tutor.py에 모았고, ANTHROPIC_API_KEY가 없으면 두 기능 모두 조용히 꺼집니다(재생은 정상).

03

CQI 누적 진화 — 계보 · 디자인 고정 · 승인제

a288849

"강의가 CQI로 개선되며 진화한다"는 아이디어를 실제로 돌아가게 만들려면 네 가지가 동시에 필요했습니다.

필요한 것어떻게 해결했나
페이지별 내용 보존 outline.json에 슬라이드별 내용 스펙을 보관하고, 진화·CQI 프롬프트에 항상 함께 전달. 슬라이드가 생성 시점부터 스펙을 갖는다.
디자인이 흔들리지 않을 것 design.json(색·폰트·레이아웃 규칙)을 버전 간 그대로 승계. 재렌더해도 시각이 유지된다.
지시가 누적될 것 cqi_ledger.json 원장에 지시문이 쌓이고 자식 버전으로 승계. 이미 반영된 항목도 applied_in_cycle 기록과 함께 계속 컨텍스트로 제공.
새 요구가 옛 요구를 이길 것 지시를 시간순으로 나열하고 "충돌 시 최신 우선"을 프롬프트에 명시. 명시적 대체는 supersede로 이전 항목을 superseded 처리.

교수자 승인 없이는 반영되지 않는다

분석 보고서에서 들어온 지시는 pending 상태로만 취입됩니다. 교수자가 검토·수정·승인한 항목만 진화에 쓰이고, 승인된 지시가 하나도 없으면 진화 요청은 400으로 거절합니다.

버전은 새 강의로 갈라진다

v1 (root)  lineage_id = 자기 lecture_id,  version 1,  parent 없음
   └─ v2   lineage_id = v1의 것,          version 2,  parent = v1
      └─ v3 ...

진화 결과는 새 lecture_id를 받습니다. 과거 버전과 그 버전이 모은 수강 데이터가 그대로 보존되므로, 개선 전후를 나란히 비교할 수 있습니다.

왜 course+week가 아니라 lineage인가

"딥러닝 기초 1주차"에 이미 서로 다른 강의가 여러 개 존재했습니다. 주차를 키로 삼으면 남의 강의의 CQI가 섞입니다. 그래서 누적의 단위를 계보(lineage)로 잡았습니다.

04

PPT 경로 제거, 웹 슬라이드 전용으로

2fa5a55

PPT 업로드와 프롬프트 생성 두 갈래를 유지하면 CQI 진화가 반쪽이 됩니다. PPT는 우리가 내용을 모르는 불투명한 입력이라, 슬라이드 자체를 개선할 수 없기 때문입니다. 웹 슬라이드로 일원화했습니다.

  • app/services/ppt_to_images.py 삭제, 업로드 엔드포인트는 POST /api/upload-prompt 하나만 남김
  • 슬라이드는 항상 outline.json(구조화된 스펙)에서 렌더 — 그래서 CQI로 슬라이드 구성 자체를 바꿀 수 있다
  • 구버전 PPT 강의를 위해 slide_spec.ensure()가 Vision으로 아웃라인을 역추출하는 레거시 호환 경로만 남김
05

형광펜이 문장에서 벗어나던 문제 — 좌표를 없애다

cff92dd

오늘 작업 중 가장 근본적인 전환입니다. 증상은 "형광펜 위치가 문장에서 벗어난다"였습니다.

진짜 원인

SVG를 쓰냐 마냐의 문제가 아니었습니다. 정보가 왕복하며 사라지는 구조가 원인이었습니다. 우리가 HTML로 슬라이드를 만들면서 글자의 정확한 위치를 이미 알고 있었는데, 그것을 PNG로 굽는 순간 레이아웃 기하 정보를 통째로 버렸고, 그 다음 Vision API에게 그림을 보여주며 좌표를 다시 추측하게 시켰습니다. 추측이 빗나가는 건 당연했습니다.

해법: 좌표를 만들지 않는다

슬라이드를 PNG가 아니라 라이브 DOM으로 재생합니다. 렌더링할 때 모든 텍스트 요소에 data-ref를 붙이고, 내레이션 세그먼트는 좌표 대신 그 요소 id를 가리킵니다. 플레이어는 [data-ref="b2"]에 클래스를 붙이기만 하면 됩니다.

이전

"highlight": {
  "x_pct": 5.0,  "y_pct": 4.0,
  "w_pct": 45.0, "h_pct": 8.0
}
→ Vision이 추측한 값
→ 폰트·줄바꿈 바뀌면 어긋남

이후

"ref": "b2"

→ 우리가 부여한 요소 id
→ 좌표가 존재하지 않으므로
   어긋날 여지 자체가 없음

따라온 변화

  • vision_analyzer.py(좌표 추측) → segment_writer.py(요소 id 지정)로 교체
  • 슬라이드 산출물이 slide_NNN.png → slide_NNN.html + 공용 slide.css
  • 공용 스테이지 모듈 slide-stage.js를 만들어 createLecture·playLecture가 같은 렌더링 사용
  • 강조 효과는 CSS로 — 형광펜(hl-marker), 밑줄(hl-underline), 체크(hl-check). 여러 줄에 걸친 문장도 box-decoration-break: clone으로 줄마다 정확히 칠해짐
  • lecture.json은 html과 image를 모두 담아 구버전 강의도 그대로 재생

의미를 잃은 녹화 버튼 제거

3950330

녹화 기능은 슬라이드가 <canvas>에 그려진 이미지라는 전제 위에 있었습니다. 라이브 DOM으로 바꾸면서 그 전제가 사라져 버튼이 아무 일도 하지 않게 됐습니다. 동작하지 않는 버튼을 남겨두면 쓰는 사람을 속이는 것이라 recorder.js와 함께 걷어냈습니다.

07

SVG 다이어그램 5종 — 개념을 그림으로

247b3db

CQI가 "벤 다이어그램으로 시각화하라"고 지시해도 결과물은 글머리표 텍스트였습니다. 관계를 그릴 수단이 없었기 때문입니다. 레이아웃을 7종에서 12종으로 늘렸습니다.

레이아웃용도실제 생성 예
venn포함 관계 · 교집합인공지능 ⊃ 머신러닝 ⊃ 딥러닝
flow순서 · 절차순전파 → 손실 계산 → 역전파 → 가중치 갱신
layers계층 구조입력층 / 은닉층 / 출력층
cycle순환 과정CQI 개선 루프
figure자유 개념도모델이 직접 그린 SVG

도형마다 따로 강조된다

data-ref를 텍스트뿐 아니라 도형에도 부여했습니다. 덕분에 내레이션이 그림을 한 부분씩 짚어갑니다. 실제 생성된 스크립트가 그 증거입니다. 

v1  "먼저 가장 바깥쪽 원, 인공지능을 보겠습니다…"
v2  "그 안쪽에 머신러닝이 포함됩니다…"
v3  "가장 안쪽 원이 바로 딥러닝입니다…"

강조된 도형만 선명해지고 나머지는 dg-dim으로 흐려집니다.

보안 — figure는 모델이 만든 SVG다

sanitize_svg()가 <script> · <foreignObject> · <iframe> · <image> · on* 핸들러 · 외부 href를 제거하고, 허용 태그 목록 밖의 태그가 있으면 통째로 거부합니다. 주입 시나리오 7종을 만들어 전부 차단되는 것을 확인했습니다.

도형의 색·선은 CSS 클래스(dg-*)로 지정해 design.json 토큰을 따릅니다. 강의가 CQI로 진화해도 다이어그램 디자인이 함께 유지됩니다.

08

AI 답변이 30초 늦게 보이던 문제

a1a17a9

기능이 잘 도는지 확인해 달라는 요청으로 시작했는데, 동작 자체는 정상이었고 대신 타이밍이 어긋나 있었습니다.

이전 — 폴링 구간

[1.5, 3, 5, 8]초

실측 생성 시간은 5.3 / 6.2 / 7.4 / 8.5 / 9.5초. 8초를 넘기면 다음 조회는 30초 주기 폴링이라 답변이 준비돼 있는데도 학생은 기다립니다.

이후

[1.5, 3, 5, 8, 12, 18, 25]초
+ 답변이 그려지면 남은 폴링 생략

단순히 늘리기만 하면 1.5초에 답이 와도 25초까지 계속 조회하므로, 조기 종료를 함께 넣었습니다.

브라우저 실측

답변 미도착 상황에서 7회 전부 발생(+1.5 +3 +5 +8 +12 +18 +25), 실제 질문에서는 8.5초에 답변이 뜨고 12·18·25초 폴링은 건너뜀을 확인했습니다. player.js?v=10 → v11로 캐시 버스터도 올렸습니다 — 올리지 않으면 이미 접속했던 학생 브라우저가 옛 파일을 계속 씁니다.

09

전 구간 논리 점검 — 오류 13건

72d7204

제작 → 운영 → 분석 → CQI 흐름을 코드 정독과 실행 테스트로 훑었습니다. 찾은 것을 전부 고쳤고, 각 항목마다 재현 테스트를 만들어 확인했습니다. (커밋 제목은 12건이지만, 주차 입력 검증을 나중에 더해 최종 13건입니다.)

#심각도문제수정
1높음 유령 강의 — createLecture에서 강의를 지워도 playLecture DB 행이 남아, 수강생 목록에 뜨지만 열면 404. 그런데 분석은 정상적으로 돌아 실체 없는 CQI 보고서가 만들어졌다. 목록에서 제외 · files_present 표시 · POST /admin/prune-missing 정리 경로 · 분석 거절
2높음 범위 밖 slide_idx — 23장 강의의 슬라이드 523에 채팅·난이도를 넣으면 HTTP 200으로 저장되지만, analytics는 range(slide_count)만 돌아 그 데이터가 통째로 사라진다. 저장 시점에 404 (require_slide)
3높음 낡은 slide_count — lecture.json이 다시 빌드돼 장수가 늘어도 DB는 옛 값 유지 → 새 슬라이드 데이터가 2번과 같은 방식으로 유실. 조회 시 자동 갱신
4중간 죽은 검증기 — validate_type이 @field_validator로 등록되지 않아 임의 event_type이 통과하고 라우터가 조용히 버렸다. 검증기 등록 + 배치를 한 건씩 검증(정상 이벤트까지 버려지지 않게)
5높음 키워드 추출기가 핵심 용어를 파괴 — 조사와 같은 글자로 끝나는 2음절 용어가 어근 1글자가 되어 사라졌다. 영문 {3,}이라 AI·ML은 아예 안 잡히고, 대신 교수님·부탁드립니다가 상위를 차지했다. 어근 규칙 재설계 · 2글자 약어 화이트리스트 · 호칭/요청 표현 제거
6높음 CQI 드리프트 방지가 항상 빈 값 — 원장이 slide_ref.title로 슬라이드 밀림을 막게 설계됐는데, 분석 보고서에 slide_title 키가 아예 없었다. lecture.json → analytics → 프롬프트 → 보고서 → 원장까지 제목 연결
7높음 중복 분석 레이스 — 가드가 processing만 검사했는데 보고서는 pending으로 생성된다. 동시 3건 → 3건 전부 수락, Claude 3회 호출. 부분 유니크 인덱스로 DB가 차단 + 재시작 시 중단 작업 복구
8중간 포털이 완성된 보고서를 감춤 — max(generated_at) 하나로 판정해, 재분석을 시작하면 완료본이 있어도 "분석 중"만 뜨고 보고서 링크가 사라졌다. 완료본 우선 + analyze_running 별도 표시
9높음 포털 로그인이 장식 — 성공 여부를 localStorage 플래그로만 남겨, 과목 삭제·유료 분석 트리거 API가 무인증이었다. 서버 발급 토큰 검증(조회는 공개 유지)
10중간 업로드 파일명이 그대로 경로에 — Path(f"/tmp/{filename}"). storage 밖에 파일이 실제로 쓰이는 것을 실증했다(관리자 인증 필요). 임시 파일 사용 + finally 정리
11중간 주차 입력 무검증 — 0주차·음수 주차·중복 주차가 모두 통과. 중복 주차는 두 카드가 같은 상태를 가리켜 분석 결과가 뒤섞인다. 1~60 범위 + 중복 시 409
12낮음 /status가 항상 0 — 웹 슬라이드로 전환했는데 slides/*.png를 세고 있었다. .html 우선 집계
13낮음 rebuild-json이 생성일을 덮어씀 — 강조 위치만 바꿔도 created_at이 오늘이 되어 목록 정렬과 분석 시간축이 흐트러졌다. 최초 생성 시각 유지

레이스 컨디션은 코드로 못 막는다

중복 분석 가드에 pending을 추가해도 여전히 뚫렸습니다. 동시 요청 셋이 모두 INSERT 전에 조회를 마치기 때문입니다(TOCTOU). 결국 DB 제약으로 내려야 했습니다. 

CREATE UNIQUE INDEX ux_cqi_reports_in_flight
ON cqi_reports (lecture_id)
WHERE status IN ('pending', 'processing');

서버가 죽으면 BackgroundTask도 사라지는데, 남은 processing 행이 인덱스를 영원히 점유해 그 강의의 재분석이 막힙니다. 기동 시 중단된 작업을 error로 정리하는 복구 로직을 함께 넣었습니다.
